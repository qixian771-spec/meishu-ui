# Phase 10 Plan 02: 嵌套预算与红线守卫

## Goal

给「玻璃套玻璃」定下可执行的预算规则：超过预算自动降级为 tint-only；同时把 R1（祖先不得有 filter）从「文档里的告诫」升级成「开发时会报警、测试会失败」。

## 为什么需要预算

`backdrop-filter` 嵌套三层以上会同时出两个问题：
1. **性能**：每层都要求浏览器额外做一次背景快照 + 模糊，层层叠加，低端设备掉帧
2. **视觉**：第 N 层采样的已经是被上层模糊过的内容，越深越糊成灰泥，玻璃感反而消失

所以规则不是「能嵌几层」，而是「**真 blur 最多两层，第三层起改用 tint-only（半透明填充 + rim，无 backdrop-filter）**」——视觉上依然是玻璃语言，但不再付模糊成本。

## Implementation Steps

### 1. depth context

新建 `src/glass/components/GlassDepthContext.ts`：

```ts
export const GlassDepthContext = createContext(0);
export function useGlassDepth(): number;
```

- `GlassShell` 提供 depth `1`
- `GlassPane` 读父 depth，自己 = 父 + 1，向下提供
- `GlassInset` 同理

### 2. 预算表（写进代码常量 + 注释）

新建 `src/glass/blurBudget.ts`：

```ts
export const BLUR_BUDGET = {
  maxBlurDepth: 2,          // 超过这个深度改 tint-only
  radius: { 1: 24, 2: 14, 3: 0 },   // px；depth 3+ 为 0 表示不模糊
} as const;

export function resolveBlurForDepth(depth: number): { blur: number; tintOnly: boolean };
```

数值可按视觉微调，但**规则必须是「深度递减 + 超预算归零」**。别把数字散在 CSS 各处——CSS 端通过原语写入的 `--glass-blur` 变量消费它。

### 3. 原语接入

- `GlassPane` / `GlassInset` 根据 `resolveBlurForDepth(depth)`：
  - 未超预算：设内联 `--glass-blur: {n}px`，CSS 里 `backdrop-filter: blur(var(--glass-blur))`
  - 超预算：加 `.is-tint-only` 类，CSS 里该类**不设** `backdrop-filter`，改用略高 alpha 的填充 + rim 保持玻璃语言
- 允许 `tintOnly` prop 手动强制（给性能敏感场景用）

### 4. dev-mode 红线守卫

新建 `src/glass/web/assertNoFilteredAncestor.ts`：

```ts
/** 仅 dev 生效：向上遍历，发现祖先有非 none 的 filter 就 console.warn（含元素定位信息） */
export function assertNoFilteredAncestor(el: HTMLElement | null): void;
```

- 在 `GlassPane` / `GlassShell` 的 `useEffect` 里调用（用 `import.meta.env.DEV` 包住，生产零开销）
- 警告文案要能自解释，例如：
  `[glass] <div.dash-doc-card> 的祖先 <div.glass-stage> 带有 filter: drop-shadow(...)，这会重置 backdrop-filter 的采样根，玻璃将静默失效。请把阴影改到玻璃元素自身的 box-shadow 上。`
- 这条守卫的价值：这个 bug 在深色主题下**肉眼看不出来**，只有浅色主题才露馅，靠人眼守不住

### 5. 测试

新建 `src/glass/__tests__/blurBudget.test.ts`：
- `resolveBlurForDepth(1|2)` 返回递减半径且 `tintOnly === false`
- `resolveBlurForDepth(3|4|10)` → `tintOnly === true`、`blur === 0`

新建 `src/glass/components/__tests__/nesting.test.tsx`（jsdom）：
- Shell > Pane > Inset > Inset 四层结构中，最内层带 `.is-tint-only`，第二层不带
- 手动 `tintOnly` prop 生效
- 单独一个 Pane（depth 1）拿到最大半径

新建 `src/glass/web/__tests__/assertNoFilteredAncestor.test.ts`（jsdom）：
- 构造「祖先带 filter」的 DOM，断言 `console.warn` 被调用且信息里含祖先标识
- 干净 DOM 不告警

## Do NOT

- 不要用 JS 测量真实性能来动态调预算（过度设计，且 SSR/测试环境不稳）
- 不要把守卫做成 throw（会炸掉别人的应用；warn 就够）
- 不要在生产构建里保留守卫的遍历开销
