# Phase 10 Plan 01: 四件玻璃原语

## Goal

产出 `GlassAtmosphere` / `GlassShell` / `GlassPane` / `GlassInset` 四个 React 原语，并把 demo 四个页面改成消费它们（而不是各自手写 class）。

## 为什么是四件而不是三件

ROADMAP 只提了 Shell / Pane / Inset。但 **R2（台面不透明 = 没有玻璃）** 说明「漂移台面」是系统的一部分而不是 demo 装饰：别人只 import 三件原语、自己配了纯色背景，玻璃就会变成灰塑料片，然后来说「你这框架不好看」。所以台面必须作为第四件原语一起交付。

## Implementation Steps

### 1. `src/glass/components/GlassAtmosphere.tsx`

包装现有 `.liquid-stage-wash`（4 个 `<span>` 色斑 + 34–52s 漂移 + `prefers-reduced-motion` 停止）。

```tsx
type GlassAtmosphereProps = {
  /** 色斑数量，默认 4 */
  blobs?: number;
  /** 关闭动画（除 reduced-motion 之外的显式关闭） */
  static?: boolean;
  className?: string;
};
```

- `position: fixed; inset: 0; z-index: 0; pointer-events: none`（沿用现状）
- 颜色全部走 `var(--accent-primary)` / `var(--accent-swatch)`，不许硬编码（R4）
- 组件注释里写清：**这不是装饰，去掉它玻璃会失效**

### 2. `src/glass/components/GlassShell.tsx`

应用外壳 / 侧栏（FR-02）。基于 `.glass-sidebar`。

```tsx
type GlassShellProps = {
  side?: React.ReactNode;      // 侧栏内容
  children: React.ReactNode;   // 主区
  /** 'glass'（默认）| 'solid'，solid 仅在明确需要不透明时用 */
  variant?: 'glass' | 'solid';
};
```

- **默认必须是透亮玻璃**：`backdrop-filter: blur(...)` + 低 alpha 背景 + rim。FR-02 的原话是「不是哑面石墨块」
- 内部渲染顺序：`<GlassAtmosphere />` 可由使用者自己放（Shell 不强塞，但 README/Skill 里写明必须有台面）
- 主区容器给 `z-index: 1`（要在台面之上，现状 `.app-main` / `.glass-sidebar` 已如此）

### 3. `src/glass/components/GlassPane.tsx`

主窗格（FR-03）。从 `src/components/liquid/SpectraGlassCard.tsx` 抽骨架。

```tsx
type GlassPaneProps = {
  /** wash 角色，决定内嵌色调深浅（同色相档位） */
  wash?: WashRole | 'none';
  /** 变体：默认 | 安静（弱化 rim/阴影）| 主视觉（更强 rim + 更大 radius） */
  variant?: 'default' | 'quiet' | 'hero';
  /** 是否挂 canvas wash（可选增强，R5） */
  canvas?: boolean;
  className?: string;
  children: React.ReactNode;
};
```

必须保留的三个视觉要素（FR-03）：
1. 顶左 specular rim（现状 `.glass-container` 的 `::before` / `.glass-rim-arc`）
2. 可读内容区（内容区不被 wash 淹没——现状靠 `.glass-container::after` 的底部渐变压暗/压亮，浅色 surface 用浅色渐变，深色用 `rgba(10,12,18,0.22)`）
3. wash hook（`--wash-*` 变量驱动）

**注意**：浮起阴影用 `box-shadow` 挂在容器自身，**不许**用祖先的 `filter: drop-shadow`（R1，这是仓库里真出过的 bug）。

`SpectraGlassCard.tsx` 的处理：改为基于 `GlassPane` 的 demo 层组合（保留它的 status pill / owner avatar 等业务化装饰），文件移到 `src/demo/components/`。它的现有测试（`__tests__/SpectraGlassCard.test.tsx`）跟着移动并保持绿。

### 4. `src/glass/components/GlassInset.tsx`

嵌套玻璃（FR-04）。用于 Pane 内的子面板 / 列表行。

```tsx
type GlassInsetProps = {
  /** 'pane'（子面板）| 'row'（列表行，更扁、hover 态） */
  as?: 'pane' | 'row';
  wash?: WashRole | 'none';
  className?: string;
  children: React.ReactNode;
};
```

- 视觉上比 Pane 更轻：更小的 blur、更细的 rim、更浅的阴影
- `as="row"` 时提供 hover 态（背景 alpha 微升 + rim 微亮），hover 色用 `color-mix(in srgb, var(--accent-primary) N%, transparent)`（R4）
- 嵌套深度的自动降级在 10-02 做，这里先把结构和 CSS 建好

### 5. 对应 CSS

在 `src/glass/css/primitives.css` 里补齐 `.glass-inset` / `.glass-inset--row` 等新类；已有的 `.glass-container` / `.glass-sidebar` 复用不重写。同步在 `src/glass/css/surface.css` 里补 `html[data-surface='light']` 覆盖——**新类必须一并写浅色覆盖，否则白瓷主题必出白字白底**（这正是本项目最初的 bug）。

### 6. demo 改为消费原语

把 `src/App.tsx`（283 行，四个页面）和 `src/components/dashboard/DashboardWorkspace.tsx`（460 行）里手写的玻璃 class 换成 `<GlassShell>` / `<GlassPane>` / `<GlassInset>`。

- demo 特有的布局类（`.dash-*` / `.tasks-layout` 等）保留，作为 `className` 传给原语
- **不要重排版面**。这一步是替换实现，不是重新设计。改完四个页面必须与改前视觉一致

### 7. 追加导出

`src/glass/index.ts` 里加上四个组件与其 props 类型。

### 8. 测试

新建 `src/glass/components/__tests__/primitives.test.tsx`（jsdom）：
- `GlassShell` 默认渲染带玻璃类，`variant="solid"` 才不带（FR-02）
- `GlassPane` 渲染 rim 元素、内容 children、`wash` prop 正确映射到 `--wash-*` 类或变量
- `GlassPane variant="hero"` 与 `"quiet"` 类名正确
- `GlassInset as="row"` 渲染行形态
- `GlassAtmosphere` 默认渲染 4 个色斑，`static` 时不带动画类
- **反向断言**：四件原语渲染出的任何元素的内联 style / class 里都不含 `filter:`（R1 的最小防线）
