# Phase 12 Plan 01: Skill 契约

## Goal

写出 `skill/meishu-ui/`，让任何 AI agent 读完就能在一个陌生项目里搭出这套玻璃美术；并且用测试保证 skill 里写的 API 名和框架真实导出**不会漂移**。

## 目标结构

```
skill/meishu-ui/
  SKILL.md                    主契约（保持精简，指向 references）
  references/
    layer-model.md            分层模型：台面 → 壳 → 窗格 → 内嵌
    tokens.md                 token 契约：类型、变量名、如何解析
    recipes-web.md            web 实现配方（backdrop-filter 实时玻璃）
    recipes-precomposited.md  渲染器实现配方（Remotion 等，预合成）
    hard-donts.md             硬禁忌（实测来源与症状）
    audit.md                  自查脚本（对比度 / 祖先 filter / 色相收敛）
```

## SKILL.md 必须包含的内容

### 1. frontmatter

```yaml
---
name: meishu-ui
description: 满屏玻璃美术系统 (full-screen glass UI) — 平台无关 token + 分层契约（台面/壳/窗格/内嵌），一套色调打到底、玻璃套玻璃、深浅色 surface。Web 走 CSS backdrop-filter 实时玻璃，视频渲染器 (Remotion) 走预合成玻璃。非 SwiftUI / 非 iOS。
---
```

**`description` 是这份 skill 唯一的检索入口**：名字 `meishu-ui` 不含任何技术信号，agent 只能靠 description 决定是否激活。所以上面这段必须保留三类关键词——中英对照的「玻璃 / glass」、技术特征词「backdrop-filter / token / surface」、平台词「Web / Remotion」——并显式声明「非 SwiftUI / 非 iOS」，与机器上已有的 `liquid-glass-design`（Apple iOS 26 那套）区分开。

不要为了简洁把 description 删短。

### 2. 何时激活

- 要给项目套上「满屏玻璃 / 玻璃套玻璃」的美术
- 要做多色调可切换的深浅色玻璃界面
- 要把同一套美术打到视频渲染（Remotion）
- 已有玻璃但「看起来像灰塑料片」需要诊断

### 3. 分层模型（SK-01 核心）

四层，顺序不可颠倒：

```
台面 Atmosphere   漂移色斑，玻璃的折射源。缺了它玻璃必然失效
  ↓
壳 Shell          应用外壳 / 侧栏，默认透亮玻璃而非哑面
  ↓
窗格 Pane         主内容面板，顶左 specular rim + wash + 可读内容区
  ↓
内嵌 Inset/Row    玻璃套玻璃，更轻的 blur 与 rim
```

每层写明：职责、必须有的视觉要素、对应的框架 API、最小 CSS。

### 4. 平台分叉（SK-04，这是这份 skill 最有价值的部分）

必须写成**两条并列路径**，让 agent 先判断目标平台再选配方：

| | Web（实时玻璃） | 渲染器（预合成玻璃） |
|---|---|---|
| 模糊 | `backdrop-filter: blur()` | 背景层单独渲一份 `filter: blur()` 副本，裁到面板形状 |
| wash | `mix-blend-mode: multiply` + canvas | 预乘算成实色直接填 |
| 分层 | `z-index` | DOM 顺序 |
| 动画 | CSS keyframes | `useCurrentFrame()` 驱动 transform |
| 色值来源 | `resolveThemeTokens()` → CSS 变量 | `resolveThemeTokens()` → 直接取 `*Rgb` 数组 |

并写明原因：视频渲染器（Remotion 的 headless Chromium）**不支持** `backdrop-filter` / `mix-blend-mode` / `background-blend-mode` / `z-index`。同时提醒：渲染器**支持** `filter`，但见硬禁忌——一加 `filter` 就会杀掉 backdrop-filter，所以这两条路径不能混用。

注意：v2.1 才做 Remotion 的真实现，本 phase 只写契约。所以 `recipes-precomposited.md` 里的代码是**方案级伪代码**，要标注「未经渲染验证，v2.1 落地时以实测为准」——不要假装验证过。

### 5. 硬禁忌（SK-04）

每条要写「症状 + 为什么 + 怎么改」，因为 agent 只有看到症状描述才会自己诊断：

1. **玻璃的任何祖先不得有 `filter`**
   - 症状：玻璃变成不透明灰板砖；深色主题下看不出来，浅色主题下明显
   - 原因：带 filter 的祖先会重置 backdrop-filter 的采样根
   - 改法：浮起阴影用玻璃元素自己的 `box-shadow`
   - 来源：本项目 2026-07-31 实测，`.glass-stage` 上一句装饰性 `drop-shadow` 让统计卡和登录卡长期是假玻璃
2. **台面不得不透明**
   - 症状：玻璃像灰塑料片，模糊了但没有折射感
   - 原因：模糊一块纯色等于什么都没做
   - 改法：加漂移色斑层
3. **不许硬编码品牌色**
   - 症状：切主题后某些元素还是旧色（淡淡的一团，容易漏检）
   - 改法：`var(--accent-primary)` 或 `color-mix(in srgb, var(--accent-primary) N%, transparent)`；阴影保持中性
4. **浅色 surface 必须写覆盖**
   - 症状：白底白字，内容完全消失
   - 改法：任何新增玻璃类都要同时写 `html[data-surface='light']` 覆盖
5. **嵌套真 blur 不超两层**
   - 症状：越深越糊成灰泥 + 掉帧
   - 改法：第三层起 tint-only

### 6. CSS-first 声明（SK-03）

明确：**不装 WebGL 也必须能出玻璃**。canvas / WebGL wash 是可选增强层，标注为 optional，并给出不带它的最小实现。

### 7. 配方（recipes）

至少三个可直接抄的配方：
- 「空项目 30 行搭出满屏玻璃」（台面 + 壳 + 一个窗格）
- 「玻璃套玻璃列表」（Pane 内放 Inset row）
- 「加一套新色调」（往 `ACCENT_THEMES` 加一项要填哪些字段、light surface 要额外做什么）

## 一致性测试（SK-02 的自动化保证）

新建 `skill/__tests__/skillConsistency.test.ts`：

- 读 `skill/meishu-ui/**/*.md` 全文
- 抽取里面出现的所有 `GlassXxx` 组件名，断言每个都在 `src/glass/index.ts` 里真实导出
- 抽取所有 `--wash-*` / `--accent-*` / `--text-*` CSS 变量名，断言每个都在 `src/glass/web/applyThemeTokens.ts` 里真的会被写入
- 抽取所有 `resolveThemeTokens` / `applyThemeTokens` 之类的函数名，断言存在
- 反向：`src/glass/index.ts` 导出的组件，skill 里至少提到一次（防止交付了但没人知道怎么用）

这条测试是 SK-02 的实质。没有它，skill 会在框架改名后静默变成一份错误说明书。
