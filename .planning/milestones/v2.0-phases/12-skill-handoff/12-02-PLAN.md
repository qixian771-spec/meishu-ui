## docs/FRAMEWORK.md（HF-02）

面向人类开发者。必须覆盖：

### 1. 定位（三句话讲清）
美术真身 = token + 契约；React/CSS 是第一个实现；同一套色以后可以打到视频渲染。别写成营销文案。

### 2. 分层模型
台面 → 壳 → 窗格 → 内嵌。配一张纯文本示意图（不要依赖图片资源）。每层写职责 + 对应 API。

### 3. 快速上手
从零开始的最小步骤，能复制粘贴跑通：
```
1. 引入 CSS：import '.../glass/css/index.css'
2. 注入 token：applyThemeTokens(resolveThemeTokens('ref123'))
3. 放台面：<GlassAtmosphere />
4. 套壳：<GlassShell side={...}>...</GlassShell>
5. 放窗格与内嵌
```

### 4. API 参考
四件原语的完整 props 表；token 层的公开函数与类型；`src/glass/index.ts` 的导出清单。**与代码保持一致**（12-01 的一致性测试也会扫这份文档，所以别写不存在的 API）。

### 5. 模糊预算
预算表、为什么递减、tint-only 是什么、怎么手动降级。引用（不要重写）`src/glass/README.md` 的那一节，两处不能有矛盾数字。

### 6. 色调包
六套色调的 id / 中文名 / surface / 适用场景一览表。怎么加第七套（要填哪些字段、light surface 要额外做什么、加完必须跑哪些审计）。

### 7. 硬禁忌
与 skill 的 `hard-donts.md` 同一份内容，人话版。至少要有「祖先 filter」和「不透明台面」两条，附症状描述——这是读者自查最有用的部分。

### 8. 如何自查
对比度审计（30 组合）、祖先 filter 查询、色相收敛检测三个脚本的用法，含 EXECUTION-BRIEF 第 5 节的两个坑（过渡节流、别采 canvas）。

### 9. 已知局限
诚实列出：
- Remotion / 视频实现尚未落地（v2.1）
- `klein` 与 `sky` 两套色调观感接近（CEO 决定保留）

## docs/WEIWEI_MIGRATION.md（HF-01）

面向喂喂项目的执行者。**注意：本里程碑不改喂喂一行代码**（明确 out of scope），这份文档只交路径。

必须覆盖：

### 1. 边界声明
先写清楚：这份文档是迁移**指南**，不是已完成的迁移。喂喂仓库的实际改造与视觉验收在 v2.1+。

### 2. 迁移前置检查
读者拿到喂喂前端后要先确认的事：
- 是不是 React？（不是则先看 FRAMEWORK.md 的「只做了 React 实现」局限）
- 现有背景是纯色还是图片？（纯色 → 必须先加台面，否则玻璃无效）
- 现有组件树里有没有祖先挂 `filter` / `transform` / `opacity`？（用自查脚本扫一遍，这是最容易踩的坑）
- 有没有深浅色主题需求？（有则一开始就要写 `data-surface` 覆盖，事后补成本高得多）

### 3. 分步迁移顺序（由外向内，每步可独立验收）
```
Step 1  引 CSS + 注入 token + 放台面        —— 此时页面背景变成漂移色斑
Step 2  外层容器换 GlassShell                —— 侧栏/顶栏变玻璃
Step 3  主要面板换 GlassPane（一次一个页面）  —— 逐页推进，随时可回滚
Step 4  列表行/子卡换 GlassInset             —— 玻璃套玻璃
Step 5  跑三个自查脚本，修对比度与色相泄漏
Step 6  接主题切换器 + 持久化
```
每步写明：改什么、怎么验收、出问题怎么回滚。

### 4. 常见冲突与解法
- 喂喂已有 UI 库（antd / MUI 等）的组件自带不透明背景 → 怎么让它半透明而不破坏其内部布局
- 全局 `overflow: hidden` 或既有 `z-index` 战争与台面层的冲突
- 喂喂现有配色与六套色调不匹配 → 加第七套色调包，而不是硬改框架
- 深色/浅色文字色阶冲突 → 一律走 `--text-*` 变量，不要保留写死的文字色

### 5. 明确不做的事
后端 / 鉴权 / 真数据 / 业务功能扩展 / 把 demo 的 `.dash-*` 布局搬过去。
