# Phase 9 Plan 01: Token 层下沉（平台无关）

## Goal

把「决定一套主题长什么样」的全部逻辑收进一个**无 DOM、无 React、无 CSS** 的纯函数层，让 `resolveThemeTokens('klein')` 在 Node 里就能拿到一份完整色表。`AccentThemeContext` 瘦身成只做两件事：消费 token + 注入 CSS 变量。

## 为什么（不要跳过）

现在「按 surface 决定文字色阶」「按亮度选 CTA 文字色」「wash 的 alpha 档位」这些**决策**和 `root.style.setProperty` 这个**注入动作**混在同一个 `useEffect` 里（`src/theme/AccentThemeContext.tsx` 78–129 行）。

后果：Remotion 那边想复用同一套色，只能把整个 React Context 搬过去，而它连 DOM 都没有。决策必须下沉，注入必须留在 web。

## 现状事实

- `src/liquid/accentThemes.ts`（393 行）已经是纯数据 + 3 个纯函数，**基本可以直接当 token 数据源**，不要重写它的数据
- `src/theme/AccentThemeContext.tsx`（152 行）里要动的三块：
  - `pickOnAccent(hex)` 24–39 行 — 纯函数，直接搬
  - `readStoredTheme()` 49–62 行 — localStorage，留在 web
  - `useEffect` 78–129 行 — 决策下沉、注入保留
- 硬编码的色阶（务必原值搬运，不要「顺手优化」）：
  - light: primary `#0F172A`、secondary `#1E293B`、muted `#475569`、faint `#64748B`、stageBg 兜底 `#F4F5F7`
  - dark: primary `#FFFFFF`、secondary `#E2E8F0`、muted `#A3B0C2`、faint `#7C8899`、stageBg 兜底 `#000000`
  - wash alpha：light `glow .35 / mid .5 / ink .75`，dark `glow .45 / mid .4 / ink .55`

## Implementation Steps

### 1. 建 token 层目录

```
src/glass/tokens/

  types.ts          ThemeTokens 等类型
  resolveTheme.ts   ★ 核心纯函数

```

约束：这四个文件**只能** import 类型和 `src/liquid/accentThemes.ts` 的数据。不许 import react、不许碰 `document`/`window`/`localStorage`、不许 import 任何 `.css`。

### 2. `contrast.ts` — 把对比度数学独立出来

从 `AccentThemeContext.tsx` 搬 `pickOnAccent`，并补上审计要用的通用函数（后面 Phase 10/11 的测试和 Skill 都会引用）：

- `relativeLuminance(rgb: [number,number,number]): number`
- `contrastRatio(a, b): number`
- `pickOnAccent(hex: string): string` — 行为与现状**完全一致**（在 `#0A0A0F` / `#F8FAFC` 中选，非法输入回 `#F8FAFC`）
- `parseHex(hex: string): [number,number,number] | null`

### 3. `resolveTheme.ts` — 核心

```ts
export function resolveThemeTokens(id: AccentThemeId | string | undefined): ThemeTokens
```

内部用 `resolveAccentTheme` 拿到 `AccentTheme`，然后把**现在散在 useEffect 里的所有决策**算完，返回一个扁平、可序列化的结果。形状建议（名字可调整，但必须与后面注入的 CSS 变量名一一对应）：

```ts
type ThemeTokens = {
  id: AccentThemeId;
  surface: 'dark' | 'light';
  accent: { primary; primarySoft; primaryBorder; swatch; onAccent };
  text: { primary; secondary; muted; faint };
  stage: { bg; bloomA; bloomB; bloomC };
  washes: Record<WashRole, {
    ink; mid; glow; rim;              // 'rgb(r,g,b)' 字符串
    inkA; midA; glowA;                // 'rgba(r,g,b,a)' 已按 surface 定好 alpha
    inkRgb; midRgb; glowRgb; rimRgb;  // [r,g,b] 数组，给 canvas / Remotion 用
  }>;
};
```

要点：
- 同时给出**字符串形式**（web 直接塞 CSS 变量）和**数组形式**（canvas / 未来 Remotion 直接算）。这是 FR-06 的实质。
- 纯函数、无副作用、同输入同输出。
- 非法 / undefined id 回落到 `DEFAULT_ACCENT_THEME`（沿用 `resolveAccentTheme` 已有的 legacy `mint→ref123` 行为）。

### 4. 新增 `src/glass/web/applyThemeTokens.ts` — 注入层

```ts
export function applyThemeTokens(tokens: ThemeTokens, root: HTMLElement = document.documentElement): void
```

把 `ThemeTokens` 写成 CSS 变量 + `data-accent-theme` / `data-surface` 两个 dataset。**变量名必须与现状逐字一致**，否则 2673 行 CSS 全部失效。现状变量名清单（一个都不能漏、不能改名）：

```
--accent-primary  --accent-primary-soft  --accent-primary-border
--accent-swatch   --accent-green（= primary，历史别名，保留）
--theme-bloom-a   --theme-bloom-b   --theme-bloom-c
--spectra-dark-bg
--text-primary  --text-secondary  --text-muted  --text-faint  --text-on-accent
--wash-{soft|mid|deep|glow|chrome}-{ink|mid|glow|rim}
--wash-{soft|mid|deep|glow|chrome}-{ink|mid|glow}-a
```

### 5. 改造 `src/theme/AccentThemeContext.tsx`

- 删掉 `pickOnAccent`（改从 `src/glass/tokens` 引）

- context value 增加 `tokens: ThemeTokens`（保留原有 `themeId` / `theme` / `setThemeId` 不动，避免 breaking demo）
