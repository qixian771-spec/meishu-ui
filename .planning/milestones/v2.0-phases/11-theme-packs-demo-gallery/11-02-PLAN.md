# Phase 11 Plan 02: Demo 画廊叙事

## Goal

把现在这个「假装是任务管理产品」的 demo 改造成**美术画廊**：进来第一眼看到的是原语和色调的展示，任务仪表盘只是其中一个「示例组合」。

## 决策来源（2026-07-31，CEO 授权规划方决定）

CEO 把「要不要做画廊改造」交给规划方定。**决定：做，并且提高规格——画廊首页是这套美术资产的门面，必须是全项目视觉最强的一页。**

理由三条：

1. **需求上必须做**：DM-01（画廊展示组合）与 DM-02（不得宣称是产品 UI）是已批准需求，跳过则里程碑不完整。
2. **误解在持续付成本**：现状首页就是任务列表（带筛选、分页、甘特图），任何人打开都以为这是个产品，然后开始提产品需求。这个误解会一直消耗 CEO 时间。
3. **画廊是资产的销售面**：这个项目的产出是「可复刻的美术资产」。资产要被采用，别人第一眼看到的就是画廊——任务四页是**证据**，画廊是**门面**。门面做得干燥，等于把最有传播力的一屏浪费掉。

配套的成本控制：不做实时代码编辑器、不做 Storybook、不重新设计配色。画廊是**已有美术的重新陈列**，不是新美术。

## 质量标准（硬性，可验收）

**画廊首屏必须能直接截图当项目封面。**

这条标准是为了防止做成一个干燥的 API 文档站——那样虽然满足 DM-01 的字面要求，但等于没做。具体含义：
- 首屏要有构图（hero 窗格 + 台面漂移 + 层次感），不是从上到下平铺的说明段落
- 首屏不要塞代码块（代码块放到下面的原语段落里）
- 六套色调下截六张图，每张都要能单独拿出去用

## Implementation Steps

### 1. 新增画廊首页

新建 `src/demo/pages/GalleryPage.tsx`，设为默认落地页。内容分四段：

1. **Hero**：项目一句话定位 —— 「可复刻的玻璃美术资产：token + 契约为真身，React/CSS 是它的第一个实现」。配一块 hero 变体的 `GlassPane`
2. **原语展示**：`GlassShell` / `GlassPane` / `GlassInset` / `GlassAtmosphere` 四件，每件一个活的实例 + 一行说明 + 该件的最小用法代码块
3. **色调包**：六套色调并排，点击即时切换整页（复用 `ThemeSwitcher`），并展示同一个 Pane 在六套色调下的样子
4. **嵌套预算**：一个 Shell > Pane > Inset > Inset 的活样本，标出每层的 blur 值和第三层的 tint-only 降级（Phase 10-02 的成果可视化）

代码块用静态字符串即可，不需要做实时编辑器（不在范围内）。

### 2. 四个现有页面降级为 sample composition

- 导航结构改成：`画廊`（默认） / `示例组合`（下含 任务管理 / 项目总览 / 设置中心 / 账号登录）
- 每个示例页顶部加一条**明显但不刺眼**的横幅：「示例组合 · 仅演示美术组合方式，非产品功能」
  - 用 `GlassInset` 实现，低饱和，不要用刺眼的黄底黑字警告条
- 不要删这四个页面（它们是最好的实战证据，也是对比度审计的测量场）
- **不要给它们加功能**（R6）

### 3. 明确免责（DM-02）

- 页面 `<title>` 与 hero 文案里不出现「喂喂」，不出现产品化承诺
- 新建或更新仓库根 `README.md`：说明这是美术资产仓库、demo 是画廊、真正的交付物是 token + 契约（Skill）+ 框架实现，并指向 `src/glass/README.md` 与（Phase 12 产出的）`docs/FRAMEWORK.md`

### 4. 测试

新建 `src/demo/__tests__/gallery.test.tsx`：
- 画廊页渲染四件原语的展示区
- 六个色调 chip 都在，点击后 `data-accent-theme` 变化
- 每个示例页渲染「示例组合」横幅（DM-02 的机器可验证证据）
- 默认路由/默认视图是画廊页，不是任务管理页

## Verification

```bash
npm test
npm run build
```

- [ ] 打开应用第一眼是画廊，不是任务列表
- [ ] 四个示例页都有免责横幅
- [ ] 画廊页 × 六套色调对比度达标（新页面纳入审计范围 → 审计矩阵从 24 组合变成 **30 组合**，全部 0 fail）
- [ ] 画廊页在浅色（白瓷）下不出现白字白底、玻璃不显灰板砖
- [ ] 嵌套预算样本能肉眼看出第三层是 tint-only（不模糊但仍像玻璃）
- [ ] **门面标准**：六套色调各截一张首屏图，逐张自问「这张能当项目封面吗」。有任何一张答不上来就继续调，别放过

### 本 plan 最大的回归风险

画廊页会把不同 `wash` 角色、不同 `variant`、六套色调**并列摆在同一屏**——这是全项目最容易踩「浅色 surface 没写覆盖 → 白底白字」的地方（本项目最初的 bug 就是这个）。每加一个展示区就顺手切到白瓷看一眼，不要攒到最后一次性审计。

## Do NOT

- 不要做实时代码编辑器 / Storybook（明确 out of scope）
- 不要给示例页加业务功能（R6）
- 不要删除现有四个示例页
- 不要在 demo 里塞真实数据源 / 后端 / 鉴权
