# Phase 11 Plan 01: 色相一致性自动检测

## Goal

把「切了主题整页都跟着变、不出彩虹」从人眼判断变成可重复运行的检测，修掉剩余泄漏，并把主题切换器提到全局可达。

## 为什么要自动化

硬编码色的泄漏是这个项目反复出问题的地方：CSS 里随手一个 `rgba(29, 78, 216, 0.28)`（克莱因蓝）在克莱因主题下完全正常，切到琥珀主题就是一团蓝光，而且很淡，人眼扫过去不一定发现。已经清了一批，但 2673 行 CSS 拆成多文件后还会有新的进来。

## Implementation Steps

### 1. 静态检测：CSS 里不许有硬编码品牌色

新建 `src/glass/__tests__/noHardcodedHue.test.ts`：

- 读取 `src/glass/css/*.css` 全部文本
- 提取所有颜色字面量（`#rrggbb`、`#rgb`、`rgb()`、`rgba()`、`hsl()`）
- 计算每个颜色的**饱和度**；断言：饱和度高于阈值（建议 HSL 饱和度 > 0.25）的颜色**不允许出现**，除非在白名单里
- 白名单只放语义色：状态绿/黄/红（成功/警告/危险）、以及 `pickOnAccent` 的两个端点 `#0A0A0F` / `#F8FAFC`
- 中性灰、黑、白（低饱和）一律放行——阴影用中性色是正确做法
- 报错信息要给出文件名、行号、色值，方便直接修

这条测试只管 `src/glass/`（框架）。`src/demo/` 可以宽松（demo 里允许出现示意用的业务色），但如果 demo 里的泄漏会影响截图验收，一并修。

### 2. 运行时检测：切主题后整页色相收敛

写一个可重复运行的浏览器审计脚本，放在 `scripts/audit-hue.md`（把脚本正文写成文档里的代码块，避免引入构建依赖；执行者贴到浏览器控制台跑）。

逻辑：
1. 切到某套主题（见下方「切换主题的正确姿势」）
2. 读 `--accent-primary`，算出目标色相 H₀
3. 遍历所有元素的 `backgroundColor` / `borderColor` / `color` / `boxShadow` 里的颜色
4. 对饱和度 > 0.25 的颜色，算色相 H，断言 `min(|H−H₀|, 360−|H−H₀|) ≤ 30°`，或落在语义色白名单
5. 输出违规清单（选择器 + 属性 + 色值 + 色相差）

六套主题各跑一遍，期望违规为 0。

### 3. 修掉检测出的泄漏

用 `color-mix(in srgb, var(--accent-primary) N%, transparent)` 或 `var(--wash-*-*)` 替换。中性阴影保持中性（不要为了「同色相」把黑阴影染成彩色——那会让整页发脏）。

### 4. wash 同色相自查（TH-02）

在 `src/glass/tokens/__tests__/` 里加用例：对每套主题，`soft/mid/deep/glow/chrome` 五个角色的 `mid` 色相互相之间差值 ≤ 40°（`glow` 角色允许更大偏移，因为它承担强调作用；`chrome` 角色允许接近中性——两者在测试里单独宽松处理，但要写注释说明为什么）。

关键是**断言它们不是随机颜色**，而不是死抠角度。

### 5. 主题切换器提到全局

现状：`ThemeSwitcher` 只在「设置中心」页存在。问题有两个——用户要切主题得先进设置页；审计脚本每次切主题都得先导航到设置页再跳回目标页（EXECUTION-BRIEF 5.2 提到的麻烦）。

做法：
- 把 `ThemeSwitcher` 放进 `GlassShell` 的顶栏（或侧栏底部），全局可达
- 设置页保留一份完整的（带说明文字的）色调选择区，两处共用同一组件
- 保持 chip 的 `data-theme-chip="<id>"` 属性（审计脚本依赖它做点击选择器，不要改名）

### 6. 持久化测试（TH-03）

新建或补充测试：
- `setThemeId` 后 `localStorage` 里 key `lingxi-accent-theme` 被写入
- 读取时非法值 / 空值回落到 `ref123`
- legacy `mint` 被迁移成 `ref123`（现有行为，别弄丢）
- `applyThemeTokens` 确实写到了 `document.documentElement`（TH-03 的「写 root 变量」）

## 切换主题的正确姿势（审计时必读）

后台 webview 会节流 CSS 过渡，切完主题立刻 `getComputedStyle` 会读到**切换前**的旧值，产出大量假结论。两种可靠做法：

```js
// A. 强制结束过渡
document.getAnimations()
  .filter(a => a.constructor.name === 'CSSTransition')
  .forEach(a => { try { a.finish(); } catch {} });

// B. 更稳：直接写 storage 后 reload，以加载态测量
localStorage.setItem('lingxi-accent-theme', 'amber'); location.reload();
```

## Do NOT

- 不要为了通过检测把中性阴影染色
- 不要动 `klein` / `sky` 的配色（CEO 已决定保留两套近似色调）
- 不要把语义状态色（成功绿 / 警告黄 / 危险红）改成跟随主题色相——那会毁掉语义
