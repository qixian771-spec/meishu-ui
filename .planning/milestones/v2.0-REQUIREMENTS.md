## v2.0 Requirements

### Framework (FR)

- [x] **FR-01**: Consumer can import glass primitives (`GlassShell`, `GlassPane`, `GlassInset` / row) from a clear package boundary (`packages/glass` or `src/glass`) without pulling task-dashboard code
- [x] **FR-02**: GlassShell renders sidebar / app chrome as translucent glass (blur + rim), not matte solid graphite by default
- [x] **FR-03**: GlassPane provides ClauseOS-style frosted pane (specular top-left rim, theme-aware wash hook, readable content zone)
- [x] **FR-04**: GlassInset supports glass-in-glass (nested panes/rows inside a Pane) with documented nest/blur budget
- [x] **FR-05**: Framework CSS/tokens are separated from demo-only layout styles (no monolith product CSS required to use primitives)
- [x] **FR-06**: Token layer is platform-agnostic plain data — importable and resolvable with no DOM, no CSS variables and no React (e.g. usable from a Node script or a Remotion composition), with the CSS-variable injection sitting in the web implementation on top of it

### Theme (TH)

- [x] **TH-01**: User can switch among ≥4 cohesive accent packs (克莱因 / 翠玉 / 天际 / 琥珀); entire chrome stays one hue family
- [x] **TH-02**: Wash roles (`soft` / `mid` / `deep` / `glow`) are tonal steps of the active pack, not mixed rainbow hues
- [x] **TH-03**: Theme choice persists (e.g. localStorage) and updates CSS variables on the document root

### Demo (DM)

- [x] **DM-01**: App presents a demo gallery / compositions showcasing Shell + Pane + Inset + themes (task UI may appear only as a sample composition)
- [x] **DM-02**: Demo does not claim to be the 喂喂 or final product UI

### Skill (SK)

- [x] **SK-01**: A Cursor/Claude Skill (`SKILL.md` + references) teaches agents the layer model, hard do/don't, and recipes to compose full-screen glass + nested glass + theme packs
- [x] **SK-02**: Skill references the same public API / token names as the framework (no contradictory class recipes)
- [x] **SK-03**: Skill documents CSS-first path; WebGL/canvas wash marked optional
- [x] **SK-04**: Skill branches by target platform — live-glass path (browser: `backdrop-filter`) vs pre-composited path (video renderers, which support none of `backdrop-filter` / `mix-blend-mode` / `z-index`) — and states the hard don'ts verified 2026-07-31: no `filter` on any ancestor of glass, never ship glass over an opaque stage

### Handoff (HF)

- [x] **HF-01**: `docs/WEIWEI_MIGRATION.md` (or equivalent) describes how to migrate 喂喂 frontend onto the glass layer (steps, boundaries, out-of-scope)
- [x] **HF-02**: `docs/FRAMEWORK.md` documents layer model, blur budget, theme packs, and import path for humans
